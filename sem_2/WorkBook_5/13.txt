Основными запросами в задаче являются:
1. Найти оценку конкретного студента по его идентификатору
2. Определить количество студентов с заданной оценкой

Значит чем быстрее мы будем получать данные после этих запросов,
тем выгоднее, но за скорость нужно платить памятью,
поэтому есть несколько вариантов решения,
в зависимости от того, на сколько сильно ограничена память

#ВАРИАНТ 1

Использовать хэш таблицу unordered_map для хранения индефикаторов студентов и их оценок 
А для получения количества студентов с конкретной оценкой использовать обычный массив из 4 элемнтов
Совокупность этих двух способов хранения дает максимальную скорость в виде O(1) для этих двух запросов,
но будет выделяться большой объем памяти, тк испоьзуется unordered_map. Немного ее можно уменьшить, используя
тип uint_8 для оценок и обычный int для id студентов. Trade-off -> минимальная скорость выполнение, максильное
потребление памяти, но легкая реализация с помощью встроенных решение unordered_map и vector


#ВАРИАНТ 2

Использование массива пар {studId, rating} для хранения индефикаторов студентов и их оценок
Для получения количества студентов с конкретной оценкой аналогично первому варианту используя массив из 4 элемнтов
Такой способ будет давать O(logN), так как мы будем использовать отсортированный массив и бинарный поиск
А массив оценок аналогично первому варианту O(1). Оценку также можно хранить в uint_8 для экономии места
Trade->off: потрбелние памяти не такое большое, но скорость уменьшается, является оптимальным решением, если
требуется меньшее потребление памяти, но при этом скорость остается логорифмической

#ВАРИАНТ 3
Начинать ID с 0 и заполнять по порядку, тогда один массив будет под отсортированные id другой под оценки, и индексация
массива оценок идет по id студента, тогда бинарным поиском мы ишем id за logN, и в массиве оценок находим оценку по id
O(1), этот вариант будет использовать немного меньше памяти чем вариант 2.


Вывод: 

Если у нас есть большое количество памяти, то мы используем вариант 1 и получаем максимальную скорость работы
системы. Самым оптимальным решением является реализация 3 Варианта, где затраты памяти и времени наиболее сбланасированы
